## 3. The setup session

### First ticket, LOCAL-1: a bug found

Started from the step (`POST /api/setup/environment/session`) at 11:40:37. The author's first tool call was `Skill`; its session plan named the container `guestbook-heron`, built from `.devcontainer/Dockerfile` `FROM cleared-v2-session`, with `install_command = npm ci`. After the plan's Go and three permissions allowed once from the inbox (a compound `git status; node --version; npm --version`, `npm ci` with the typecheck, the commit), it committed the three files. The check failed three times the same way:

```
Environment check, round 1: the branch's image could not be built. The last lines of the build:

#2 [internal] load metadata for docker.io/library/cleared-v2-session:latest
#2 ERROR: pull access denied, repository does not exist or may require authorization: server message: insufficient_scope: authorization failed
...
Dockerfile:3
   3 | >>> FROM cleared-v2-session
```

At round 3 (11:44:38) the ticket went back to Todo with "The environment check still failed after 3 rounds". Between rounds the author searched for the image's tag; one request, a `grep` across `/var/lib/cleared`, `/etc/cleared` and `/opt`, was denied from the inbox.

The cause is Cleared's: the Environment template and the check's own advice say to start from `cleared-v2-session`, and P254 says that name under any tag is this install's, but only a devcontainer `image` was mapped to this install's tag; a `FROM` line of its Dockerfile went to Docker Hub as written. Fixed in this lane (`onSessionImage` in `src/container/prepared.ts`, test first in `test/container/prepared.test.ts`). LOCAL-1 was closed and moved to Done by hand, and the service started again on the fixed code.
